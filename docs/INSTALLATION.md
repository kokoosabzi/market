# نصب، اجرا و نگهداری Market

> این سند راهنمای محیط توسعه و مشخصات انتشار هدف را پوشش می‌دهد؛ نصب‌کنندهٔ ویندوز هنوز ساخته یا آزموده نشده است.

## 1. محیط توسعه
- نصب Node.js نسخهٔ 22 و npm فقط روی رایانهٔ توسعه‌دهنده.
- اجرای `npm install` برای نصب وابستگی‌ها.
- اجرای `npm test` برای آزمون پایگاه داده و migrationها.
- اجرای `npm start` برای بازسازی ماژول بومی SQLite و اجرای پوستهٔ Electron.
- ساخت بستهٔ ویندوز با `npm run dist:win` روی محیط سازگار؛ خروجی هنوز باید جداگانه آزموده شود.

## 2. هدف انتشار
- نصب‌کنندهٔ دسکتاپ برای ویندوز.
- اجرای آفلاین پس از نصب.
- عدم نیاز کاربر نهایی به نصب جداگانهٔ Node.js.
- نگهداری داده‌های کاربر خارج از پوشهٔ برنامه.

## 3. محل داده
مسیر نهایی پایگاه داده و پشتیبان‌ها باید پیش از انتشار تعیین و در برنامه نمایش داده شود. حذف یا ارتقای برنامه نباید به‌طور پیش‌فرض داده‌های کاربر را حذف کند.

## 4. نصب و ارتقا
- آزمون نصب تمیز و اجرای اولیه.
- بررسی دسترسی نوشتن در مسیر داده.
- اجرای migrationهای نسخه‌دار پیش از استفاده از schema جدید.
- تهیهٔ پشتیبان پیش از migrationهای پرخطر.
- توقف امن در صورت شکست migration؛ بدون ادامه با schema ناسازگار.
- آزمون ارتقا از نسخهٔ قبلی با حفظ داده‌ها.

## 5. پشتیبان‌گیری
- تهیهٔ پشتیبان سازگار با SQLite؛ کپی سادهٔ فایل در زمان نوشتن فعال، بدون راهبرد سازگاری، کافی فرض نشود.
- نمایش مسیر، زمان و نتیجهٔ پشتیبان‌گیری.
- اعتبارسنجی فایل پشتیبان قبل از بازیابی.
- پیشنهاد حفظ نسخهٔ قبلی داده قبل از جایگزینی.
- آزمون بازیابی در مسیر/محیط کنترل‌شده.

## 6. حذف برنامه
فرایند حذف برنامه نباید داده‌های کاربر را بی‌صدا پاک کند. اگر حذف داده‌ها ارائه می‌شود، باید انتخاب جداگانه، هشدار روشن و تأیید صریح داشته باشد.

## 7. گزارش خطا
راهنما باید روش یافتن نسخهٔ برنامه، محل گزارش خطا و محل داده را توضیح دهد. گزارش‌ها نباید اطلاعات حساس غیرضروری را افشا کنند.
